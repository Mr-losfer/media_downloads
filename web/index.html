    REST API

    所有接口都接受 Authorization: Bearer <API Key>；浏览器内也可用登录 Cookie。 播放类接口额外支持 ?token=<API Key>，方便 <video> 与 EventSource 直接使用。

    连接信息

    Base URL
    http://…
    鉴权
    Authorization: Bearer <API Key>
    API Key
    「设置」页可查看、复制
    编码
    请求与响应均为 application/json; charset=utf-8

    通用约定与提交示例

    全部接口均以 application/json; charset=utf-8 收发，路径参数写在 URL 里， 请求体为单个 JSON 对象。除 /api/health 外都需要鉴权，三种等价方式：

    # ① Bearer（脚本 / 第三方集成推荐）
curl -H "Authorization: Bearer $VF_KEY" "/api/tasks"

# ② 登录 Cookie（浏览器自动带）
curl -b "ms_session=..." "/api/tasks"

# ③ query token（只给播放 / SSE / 下载类接口用，方便塞进 <video> 或 EventSource）
curl "/api/tasks/<id>/stream?token=$VF_KEY"
    API Key 在「设置 → 安全」里查看与重置，形如 ms_xxxxxxxx。 统一错误格式：{"error":"中文说明"}；成功按接口返回对象或数组。 所有写接口都是幂等程度不同，请以返回的 ok / 任务对象为准，不要只看 HTTP 码。

    提交下载：完整示例与响应

    curl -X POST "/api/tasks" \
  -H "Authorization: Bearer $VF_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com/hls/index.m3u8",
    "title": "我的视频",
    "save_dir": "/downloads/hdd",
    "headers": { "Referer": "https://example.com/", "Cookie": "sid=abc" },
    "trim_enabled": false
  }'

# 201 Created
{
  "id": "t_7f3a2b1c",
  "url": "https://example.com/hls/index.m3u8",
  "title": "我的视频",
  "status": "queued",
  "progress": 0,
  "kind": "hls",
  "format": "mp4",
  "save_dir": "/downloads/hdd",
  "created_at": "2026-11-15T10:00:00Z"
}

# 409 Conflict（链接防重命中，直接拦截，不创建任务）
{
  "error": "已拦截重复下载：该链接已存在下载任务",
  "duplicate": true,
  "reason": "url",              // 或 "title"（开启标题防重后）
  "task_id": "t_7f3a2b1c"
}
    请求字段类型必填说明
    urlstring是http/https 直链：m3u8 / mp4 / flv / ts 等；也可先走 /api/parse 解析成多条直链
    titlestring否保存文件名，不要写扩展名，服务端按探测到的容器自动补
    save_dirstring否必须是「设置 → 存储」里配置过的目录，留空用默认目录
    headersobject否防盗链请求头，键值对字符串
    批量提交：公众号解析等场景会一次拿到多个 item，前端对每条各发一次 POST /api/tasks； 重复项返回 409 时会被统计为「跳过 N 个重复」，其余照常入队，不会互相阻塞。

    链接解析（插件化）

    首页粘贴 https://mp.weixin.qq.com/s/… 时，会先交给解析插件：展示文章标题、封面、作者、简介、 发布时间、图片与正文摘要，并把解析出的视频直链列成可勾选的下载对象（一般是 mp4，无需 ffmpeg 合成）。 普通直链不受影响，仍按原流程直接下载。

    # 列出已注册的解析插件
curl "/api/parsers" -H "Authorization: Bearer $VF_KEY"

# 统一解析入口：未命中 {"matched":false}，命中返回 result
curl -X POST "/api/parse" \
  -H "Authorization: Bearer $VF_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://mp.weixin.qq.com/s/epF_Tih8U0wNUUazf0TrsA"}'
    命中的插件由服务端注册表决定，前端只认统一的 result 结构 （title / cover / author / description / images / items）。 新增站点支持只需在 internal/parser 实现 Parser 接口并注册一行，不用改前端与下载引擎。 公众号解析服务地址可用环境变量 MS_MP_PARSE_API 换成自建服务。

    提交下载

    curl -X POST /api/tasks \
  -H "Authorization: Bearer $VF_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com/hls/index.m3u8",
    "title": "我的视频",
    "save_dir": "/downloads/hdd",
    "headers": { "Referer": "https://example.com/" }
  }'
    title 不用写扩展名，服务端按探测到的容器自动补 .mp4； save_dir 必须已在设置里配置；headers 可选，用于防盗链。
    防重复下载：同一链接已存在任务时返回 409 并带 {"duplicate":true,"reason":"url"}，直接拦截不创建任务； 在「设置 → 下载」开启标题防重后，同标题也会拦截（reason:"title"）。失败 / 已取消的任务不参与判断。

    插件管理 API

    插件页的所有操作都有对应 REST 接口，方便脚本化开发、CI 校验与第三方集成。 {id} 是 plugin.json 里的 id，也是插件文件夹名。

    方法路径说明
    GET/api/plugins插件列表（含 config_schema、配置值、文件清单、warnings）
    POST/api/plugins新建脚手架（或传 bundle 内联导入）
    POST/api/plugins/upload上传 zip（multipart file / raw zip / JSON files）
    POST/api/plugins/validate只校验 plugin.json，不安装
    POST/api/plugins/reload重新扫描目录、重载全部插件
    GET/api/plugins/{id}单个插件完整信息
    PUT/api/plugins/{id}覆盖 plugin.json（可包在 manifest 里）
    DELETE/api/plugins/{id}删除插件（内置禁止）
    GET/api/plugins/{id}/config读 config_schema 与当前配置值
    POST/api/plugins/{id}/config保存配置值（支持 {"config":{...}} 或直接对象）
    POST/api/plugins/{id}/toggle启停，{"enabled":true}，不传则取反
    POST/api/plugins/{id}/copy另存为新插件（内置会自动转 declarative 模板）
    POST/api/plugins/{id}/test样例链接跑一次，返回 result + trace
    POST/api/plugins/{id}/debug调试运行（含请求/响应片段、日志、耗时）
    GET/api/plugins/{id}/files文件清单
    GET/api/plugins/{id}/file?path=读文件内容（text/plain）
    PUT/api/plugins/{id}/file写文件 {"path":"main.go","content":"..."}
    DELETE/api/plugins/{id}/file?path=删文件
    POST/api/plugins/{id}/patch差量修改 {"ops":[...]}
    POST/api/plugins/{id}/build编译 Go 插件
    POST/api/plugins/{id}/reload重载单个（实际全局重载）
    GET/api/plugins/{id}/export导出 zip（不含编译产物）
    GET/api/marketplace市场列表（?force=1 跳过缓存）
    POST/api/marketplace/refresh强制刷新市场
    POST/api/marketplace/install安装 / 更新 {"id":"..."}
    GET/api/marketplace/config读市场源配置
    PUT/api/marketplace/config改市场地址 / 代理 / 缓存

    错误响应

    状态码含义处理方式
    201创建成功提交任务 / 新建插件 / 市场安装
    400参数不合法看 error 字段，多为 URL、目录或 plugin.json 校验失败
    401未授权检查 API Key，或重新登录
    404任务 / 插件 / 文件不存在可能已被删除
    409冲突重复下载拦截（duplicate:true, reason:url|title, task_id）或文件尚未就绪
    415Content-Type 不支持MCP 端点要求 application/json
    429登录尝试过多等 5 分钟再试
    502上游失败插件解析失败 / 市场下载失败，响应里带 trace
    503服务未就绪插件系统未初始化

    插件开发文档

    Media Super 的解析能力完全插件化。一个插件 = 一个文件夹 + 一份 plugin.json， Go 插件可以包含多个主要代码文件。插件自己声明「匹配哪些域名」「需要用户填哪些配置」， 主程序在首页提交链接时按域名自动挑选插件运行，产出统一结果后把视频交给下载引擎。

    1. 三种引擎，先选一种

    引擎要不要写代码要不要编译适用场景
    declarative不写，只写规则零编译，上传即用绝大多数「调一个 JSON 接口拿直链」的站点，推荐
    go写 Go（可多文件）需要编译成可执行文件需要签名计算、抓 HTML、复杂逻辑、自定义协议
    builtin编译进主程序随主程序发布官方内置（当前仅「微信公众号解析」）
    为什么 Go 插件不用 .so？ Go 的 plugin 包要求主程序与插件的 Go 版本、依赖版本完全一致， NAS 上还分 x86 / arm，用户上传源码无法直接加载。Media Super 采用独立可执行文件 + stdin/stdout JSON 行协议 （Hashicorp go-plugin 思路）：跨版本、跨架构、可沙箱、崩溃不影响主服务。NAS 没装 Go 时可在开发机编译好只上传 bin/， 或者直接改用 declarative 引擎。

    2. 目录结构

    <数据目录>/plugins/
  _state.json              运行期状态（启停 / 配置值 / 来源），自动生成，不要提交
  _market.json             市场源配置，自动生成
  my_site/                 ← 一个插件就是一个文件夹
    plugin.json            ← 必需，唯一权威元数据
    main.go                Go 引擎：SDK 协议入口
    parse.go               Go 引擎：业务逻辑（可拆任意多个 .go 文件）
    go.mod                 Go 引擎：模块文件（只用标准库即可）
    README.md              说明文档
    icon.png               可选图标
    bin/my_site            编译产物（不导出、不入库）
    插件目录里的文件可以用插件页「文件」按钮在线编辑，也可以用 MCP 的 plugin_write_file / plugin_patch 差量修改。 _state.json 集中保存启用状态与配置值，不写进插件目录，所以插件文件夹可以原样提交 Git、导出给别的机器。

    3. plugin.json 全字段

    字段类型必填说明
    idstring是2–48 位，小写字母开头，只含 a-z 0-9 _ -。必须与文件夹同名，全局唯一
    namestring是插件列表里显示的名称
    versionstring是语义化版本，如 1.0.0；市场用它判断可更新
    enginestring是declarative / go / builtin
    description / author / homepage / tags / changelogstring / array否展示用元信息；tags 是字符串数组
    iconstring否相对插件目录的图标路径
    matchobject否决定提交哪种链接时运行本插件，详见第 4 节
    config_schemaarray否用户可视化配置选项，非空时列表自动出现「配置」按钮，详见第 5 节
    capabilitiesobject否{ "parse": true, "configurable": true }；无 parse 能力的插件不参与链接解析
    declarativeobjectengine=declarative 时必填HTTP 请求 + 响应字段映射规则，详见第 6 节
    entryobject否Go 引擎：sources（参与编译的 .go 文件，留空则自动扫描）、binary（产物相对路径，默认 bin/<id>）
    min_app_versionstring否要求的最低 Media Super 版本，仅作说明
    builtinbool否内置插件标记，禁止删除；第三方插件不要写
    上传 / 保存前会做严格校验：JSON 里出现未知字段、id 格式错、engine 不认识、正则写错、 select 缺 options 等都会给出具体中文错误，不会静默装上坏插件。

    4. match：发现哪一种域名时运行

    "match": {
  "domains": ["mp.weixin.qq.com", "*.example.com"],
  "url_patterns": ["^https://example\\.com/video/\\d+$"],
  "path_prefixes": ["/s", "/video"],
  "schemes": ["https"],
  "extensions": [".m3u8", ".mp4"],
  "priority": 10
}
    字段含义
    domains精确域名或 *.example.com 通配（同时匹配裸域与子域）。内部是「或」
    url_patternsGo 正则，匹配整条 URL；写了它就必须至少命中一条
    path_prefixesURL 路径前缀，如 /s、/video
    schemes允许的协议，留空 = http/https 都行
    extensions允许的扩展名（带点、小写），用于只接管直链
    priority数值越大越先匹配，默认 0。多个插件都能命中时只运行第一个
    各字段之间是「与」关系；整条 match 为空的插件不会自动接管任何链接， 但仍可用「测试」按钮或 MCP plugin_test 显式调用，适合做工具型插件。 内置公众号插件优先展示配置项，验证时可把它的开关关掉再测同域名插件。

    5. config_schema：代码中定义的可视化配置

    每写一项，插件列表就多一个「配置」按钮；点击弹窗按 type 渲染控件，保存后写入 _state.json。

    "config_schema": [
  { "key": "api_base", "label": "解析接口", "type": "url", "required": true,
    "default": "https://example.com/api/parse", "desc": "GET 接口，接受 url 参数", "group": "接口" },
  { "key": "api_token", "label": "Token", "type": "password", "default": "", "group": "接口" },
  { "key": "timeout_sec", "label": "超时（秒）", "type": "number",
    "default": 15, "min": 3, "max": 60, "group": "接口" },
  { "key": "quality", "label": "清晰度", "type": "select", "default": "best",
    "options": [{"label":"最高","value":"best"},{"label":"最低","value":"worst"}] },
  { "key": "auto_download", "label": "解析后自动下载", "type": "switch", "default": false },
  { "key": "extra_headers", "label": "附加请求头", "type": "textarea", "default": "" }
]
    type控件可用属性
    text单行文本key（必填、唯一）
    label 显示名
    desc 帮助文字
    default 默认值
    required 必填校验
    placeholder
    group 分组标题
    min / max 数字范围
    options select 选项
    password密码框（不回显）
    number数字输入（带 min/max 校验）
    switch开关
    select下拉选择（必须给 options）
    textarea多行文本
    url地址输入（校验 http/https）
    注入方式：声明式规则里写 {{config.api_base}}，Go 插件里从 stdin 的 config 对象读。约定键 auto_download: true 会让前端解析卡片自动把全部视频加入下载队列。 新增配置项后重载会补默认值，已有用户值不会被覆盖。

    6. declarative 规则（零编译，推荐）

    "declarative": {
  "request": {
    "method": "GET",
    "url": "{{config.api_base}}",
    "query": { "url": "{{source_url}}", "quality": "{{config.quality}}" },
    "headers": { "Accept": "application/json",
                 "Authorization": "{{config.api_token}}" },
    "body": "",
    "timeout_sec": 15
  },
  "response": {
    "format": "json",
    "success_when": "code == 1",
    "error_field": "msg",
    "fields": {
      "title": "data.title", "cover": "data.cover",
      "author": "data.author", "description": "data.description",
      "publish_time": "data.publish_time", "content": "data.content",
      "source_url": "data.source_url", "images": "data.images"
    },
    "items": {
      "from": "data.movie_down_url",
      "url": "{{value}}",
      "title": "{{title}} · {{index1}}",
      "cover": "{{cover}}", "page": "{{source_url}}", "id": "{{item.id}}",
      "kind": "video", "format": "mp4",
      "headers": { "Referer": "https://mp.weixin.qq.com/" },
      "max": 100
    }
  }
}
    位置说明
    request.methodGET（默认）或 POST
    request.url / query / headers / body全部支持 {{...}} 模板；空值头会自动跳过；body 非空时自动补 Content-Type: application/json
    request.timeout_sec3–60 秒，默认 15；响应体上限 8 MB
    response.success_when简单断言，如 code == 1、data.ok == true、errcode != 0；失败时取 error_field 的点路径作为提示
    response.fields结果字段 → 响应点路径。可用键：title / cover / author / description / publish_time / content / source_url / images / plugin_name。content 会剥掉 HTML 标签压成摘要
    response.items.from数组所在点路径，如 data.list；也能直接放字符串数组
    response.items.*url / title / cover / page / id / headers 都支持模板；kind 默认 video，format 默认 mp4，max 默认 100
    点路径支持 data.title、data.list[0].url。
    模板变量：{{config.<key>}}、{{source_url}}（或 {{url}}）、 {{title}}、{{cover}}、{{value}}（数组元素是字符串时）、 {{item.url}}（元素是对象时）、{{index}}（0 起）、{{index1}}（1 起）。 变量缺失时替换为空串，不会让整次解析崩掉。

    7. Go 插件 SDK 协议

    插件编译成独立可执行文件，主程序 exec 它并通过 stdin/stdout 传一行 JSON。只用标准库即可。

    // stdin（一行）
{"url":"https://site.com/page","config":{"api_base":"https://..."},"mode":"debug"}

// stdout（最后一行，前面允许打日志）
{"ok":true,"result":{"plugin":"my_site","plugin_name":"我的插件",
  "source_url":"https://site.com/page","title":"标题","cover":"","author":"",
  "description":"","publish_time":"","content_text":"","content_len":0,
  "images":[],"items":[
    {"url":"https://.../a.mp4","title":"第 1 集","kind":"video","format":"mp4",
     "headers":{"Referer":"https://site.com/"}}
  ],"extra":{}},"logs":["GET ..."]}

// 失败
{"ok":false,"error":"解析服务返回 HTTP 502","logs":[]}
    约定要求
    stdin读一行 JSON：url 原始链接、config 配置值对象、mode = parse / debug
    stdout最后一行必须是 JSON：ok + result，或 ok:false + error；可带 logs
    stderr任意日志，debug 模式会回传到界面
    超时30 秒未退出判定失败；退出码非 0 也判定失败
    多文件全部放 package main，在 entry.sources 列出或留空自动扫描 *.go
    仓库 marketplace/go_demo/ 是一份能直接编译运行的完整示例（main.go 管协议、parse.go 管业务）。 没有 Go 工具链的设备：在开发机 go build 后只把可执行文件放进 bin/ 再上传，或改用 declarative 引擎。

    9. 在线插件市场（对接 Git）

    市场就是一个 Git 仓库：根目录放 marketplace.json，每个插件一个文件夹。 git push 即上架，不需要额外服务器。默认指向 Mr-losfer/media_downloads 的 marketplace/ 目录，可在「市场源设置」里换成任意仓库直链。

    {
  "schema_version": "1",
  "name": "Media Super 官方插件市场",
  "owner": "Mr-losfer",
  "repo": "Mr-losfer/media_downloads",
  "updated_at": "2026-11-15",
  "base_url": "marketplace",       // 相对 marketplace.json 所在目录，也可写绝对 URL
  "plugins": [
    {
      "id": "json_api_parser", "name": "通用 JSON 解析接口",
      "version": "1.0.2", "description": "对接任意返回 JSON 的自建服务",
      "author": "Media Super", "engine": "declarative",
      "tags": ["通用", "模板"],
      "path": "json_api_parser",   // 相对 base_url 的文件夹
      "files": ["plugin.json", "README.md"],   // 文件夹内要下载的文件
      "min_app_version": "2.5.9"
    }
  ]
}

    上架步骤：① 把插件整个文件夹放进仓库 marketplace/<id>/； ② 在 marketplace.json 的 plugins 里加一条，列全 files； ③ commit + push；④ 客户端点「刷新市场」即可看到，点安装会逐文件下载并落地到插件目录。

    国内 NAS 直连 raw.githubusercontent.com 常失败，客户端会自动先走 gh-proxy 代理、再回退直连； 市场地址、代理前缀、缓存时长都可在「市场源设置」里改。Go 插件的 bin/ 编译产物不要提交， 安装后由用户自行编译或改上传已编译产物。

    10. 常见问题

    现象原因与处理
    提交链接没走插件检查 match.domains 是否写对、插件是否启用、是否有更高 priority 的插件抢先命中
    提示「解析地址不合法」{{config.api_base}} 还没在配置弹窗里填，或填的不是 http(s)
    解析成功但 0 个视频items.from 的点路径不对；用「调试」看返回体，或把 from 改成真实数组路径
    提示「插件尚未编译」engine=go 但缺 bin/ 产物；点「编译」，或改 declarative
    编译报「没有 Go 工具链」NAS 上正常。开发机编译后上传产物，或改用 declarative 引擎
    上传 zip 报缺少 plugin.jsonzip 顶层多套了一层目录是允许的，但 plugin.json 必须在插件文件夹根部
    改了 plugin.json 不生效点「重载」；id 不能改（与目录名绑定），改 id 要新建插件

    把 Media Super 接到任何支持 Model Context Protocol 的 Agent 上，让模型自己提交下载、查进度、改名、删文件。 走 JSON-RPC 2.0 over HTTP，用同一个 API Key 鉴权。

    防重复下载

    提交任务时按链接判断是否重复：同一个链接已有任务（排队 / 下载中 / 已完成）会直接拦截，不再创建第二条。判断会忽略 # 片段、统一协议与主机名大小写，下载用的链接本身不会被改写。

    默认关闭。空标题不参与判断；失败或已取消的任务不拦截，可直接重新提交或用「重试」。开启后，批量下载里标题相同的多个视频只会保留第一个。想重新下载已完成的同一链接，先到任务页删除那条任务记录即可。

    去除片头 / 片尾

    按 m3u8 分片计数：开头跳过 N 片、结尾丢掉 N 片，中间部分才拼接。适合开头或结尾有黑屏、台标、广告的源。只对 HLS 生效，设置只影响之后提交的任务。

    分片时长因源而异（常见 2–10 秒/片），N 超过总片数时会自动保留至少 1 片。

    保存目录

    第一行是默认目录；容器内路径需在 docker-compose 里挂载好。

    自动清理

    只清理磁盘文件，任务记录继续保留，方便回看。
