    REST API

    所有接口都接受 Authorization: Bearer <API Key>；浏览器内也可用登录 Cookie。 播放类接口额外支持 ?token=<API Key>，方便 <video> 与 EventSource 直接使用。

    连接信息

    Base URL
    http://…
    鉴权
    Authorization: Bearer <API Key>
    API Key
    「设置」页可查看、复制
    编码
    请求与响应均为 application/json; charset=utf-8

    提交下载

    curl -X POST /api/tasks \
  -H "Authorization: Bearer $VF_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com/hls/index.m3u8",
    "title": "我的视频",
    "save_dir": "/downloads/hdd",
    "headers": { "Referer": "https://example.com/" }
  }'
    title 不用写扩展名，服务端按探测到的容器自动补 .mp4； save_dir 必须已在设置里配置；headers 可选，用于防盗链。

    查询与操作

    # 列表（status=queued|running|merging|completed|failed|canceled|active）
curl "/api/tasks?status=active&limit=50" -H "Authorization: Bearer $VF_KEY"

# 单个任务
curl "/api/tasks/<id>" -H "Authorization: Bearer $VF_KEY"

# 改名
curl -X PATCH "/api/tasks/<id>" \
  -H "Authorization: Bearer $VF_KEY" -H "Content-Type: application/json" \
  -d '{"title":"新名字"}'

# 取消 / 重试
curl -X POST "/api/tasks/<id>/cancel" -H "Authorization: Bearer $VF_KEY"
curl -X POST "/api/tasks/<id>/retry"  -H "Authorization: Bearer $VF_KEY"

# 删除（file=true 同时删文件）
curl -X DELETE "/api/tasks/<id>?file=true" -H "Authorization: Bearer $VF_KEY"

    在线播放

    <video controls src="/api/tasks/<id>/stream?token=$VF_KEY"></video>

# 支持 HTTP Range（拖动进度条 / 断点续传）
curl -H "Range: bytes=0-1023" "/api/tasks/<id>/stream?token=$VF_KEY" -o /tmp/head.bin
curl "/api/tasks/<id>/download?token=$VF_KEY" -O -J

    实时事件（SSE）

    curl -N "/api/events?token=$VF_KEY"

event: hello     {"version":"1.0.0"}
event: snapshot  [ …任务数组… ]
event: task      { …单个任务，变化即推（500ms 节流）… }
event: stats     { …统计… }
event: task.deleted {"id":"…"}
: ping           每 20 秒心跳
    也可以配置 Webhook：服务端在 task.created / started / completed / failed / canceled 时 POST JSON， 带 X-VF-Event 与 X-VF-Signature: sha256=<HMAC-SHA256(secret, body)>，失败重试 2 次。

    错误响应

    状态码含义处理方式
    400参数不合法看 error 字段，多为 URL 或目录不在允许列表
    401未授权检查 API Key，或重新登录
    404任务 / 文件不存在可能已被删除
    409文件尚未就绪任务还没 completed，稍后再取
    429登录尝试过多等 5 分钟再试

    MCP 服务

    把 VidFetch 接到任何支持 Model Context Protocol 的 Agent 上，让模型自己提交下载、查进度、改名、删文件。 走 JSON-RPC 2.0 over HTTP，用同一个 API Key 鉴权。

    端点

    URL
    /mcp
    传输
    Streamable HTTP（POST JSON-RPC 2.0）
    协议版本
    2025-06-18（兼容 2025-03-26 / 2024-11-05）
    鉴权
    Authorization: Bearer <API Key>
    方法
    initialize · tools/list · tools/call · ping

    客户端配置

    支持 HTTP 直连的客户端（Cline / Cherry Studio / 自研 Agent）直接填 URL 和 Bearer 头：

    {
  "mcpServers": {
    "vidfetch": {
      "type": "http",
      "url": "/mcp",
      "headers": { "Authorization": "Bearer vf_xxxxxxxx" }
    }
  }
}

    只能 stdio 的客户端（如 Claude Desktop）用同一份二进制转发到远端：

    {
  "mcpServers": {
    "vidfetch": {
      "command": "docker",
      "args": ["exec", "-i", "vidfetch", "/usr/local/bin/vidfetch",
               "-stdio", "-remote", "http://127.0.0.1:8080", "-key", "vf_xxxxxxxx"]
    }
  }
}

    原始调用示例

    curl -X POST /mcp \
  -H "Authorization: Bearer $VF_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/call",
    "params": {
      "name": "submit_download",
      "arguments": { "url": "https://example.com/a.m3u8", "title": "测试" }
    }
  }'
    返回的 result.content[0].text 是 JSON 字符串；工具内部出错时返回 isError: true， 只有协议层错误才用 error.code（-32700 解析失败 / -32601 方法不存在 / -32602 参数错误）。

    下载性能

    低配设备建议：并发任务 2、分片连接 8。两者相乘即最大同时连接数。

    保存目录

    第一行是默认目录；容器内路径需在 docker-compose 里挂载好。

    事件与清理

    事件类型：task.created / started / completed / failed / canceled， 请求头带 X-VF-Event 与 X-VF-Signature。
